# PIR 영상 병합 & 유튜브 업로더

여러 개의 영상을 **촬영 시작시간 순서대로(또는 직접 정한 순서로)** 하나의 파일로 합쳐서 **유튜브에 한 번에 업로드**하는 개인용 관리자 웹앱입니다.
업로드 제목은 기본으로 `YYYYMMDD PIR풋` (예: `20261007 PIR풋`) 형식으로 만들어집니다.

- Python + **FastAPI**, DB 없음 (관리자 계정 1개를 `.env`에 저장)
- 노트북/데스크톱/모바일 브라우저에서 접속 (반응형)
- 3GB급 대용량 영상 대응: 조각(8MB) 업로드, 끊겨도 자동 재시도·이어받기
- ffmpeg로 병합, YouTube Data API v3로 업로드

## 1. 주요 기능

| 기능 | 설명 |
|---|---|
| 관리자 로그인 | `.env`의 ID/비밀번호 1개. 10분 내 5회 실패하면 잠시 차단, 세션은 12시간 유지 |
| 여러 영상 한 번에 업로드 | 드래그 앤 드롭 또는 파일 선택(여러 개). 모바일도 가능 |
| 촬영 시작시간 표시 | 영상 메타데이터의 촬영시각을 한국시간(KST)으로 카드에 크게 표시. 없으면 파일 수정시간을 쓰고 **"추정"** 표시 |
| 순서 지정 | 카드를 **드래그**하거나 왼쪽 **번호를 직접 입력**, "시작시간순 정렬" 버튼. 앞 영상보다 촬영시간이 빠르면 "순서 확인" 경고 |
| 자동 제목 | 가장 이른 촬영일 기준 `YYYYMMDD PIR풋` (수정 가능) |
| 병합 | 규격이 같으면 **재인코딩 없이** 이어붙임(빠름·화질 그대로). 다르면 첫 영상 기준으로 맞춰 재인코딩 |
| 안전 모드 | 체크하면 항상 재인코딩. 휴대폰 영상이 이어붙인 뒤 끊겨 보일 때 사용 |
| 미리 보기 | "병합만 하고 미리 보기" → 관리자 화면에서 병합 결과를 재생해 보고, 괜찮으면 그 파일 그대로 업로드 |
| 유튜브 업로드 | resumable 업로드, 진행률 표시, 완료 시 링크 표시. 공개 설정은 비공개(기본)/일부 공개/공개 |
| 자동 정리 | 업로드 성공 시 원본·병합본을 서버에서 삭제 |

지원 확장자: `mp4, mov, m4v, mkv, avi, webm, mts, m2ts, 3gp`

## 2. 프로젝트 구조

```
.
├─ app/
│  ├─ main.py          # FastAPI 앱, 로그인/로그아웃, 개인정보처리방침·약관 페이지
│  ├─ auth.py          # .env 계정 확인, 로그인 시도 제한
│  ├─ config.py        # 환경변수(.env) 로딩
│  ├─ videos.py        # 청크 업로드, ffprobe 메타 추출(촬영시간 등), 목록/삭제
│  ├─ merge.py         # ffmpeg 병합 (복사 / 재인코딩)
│  ├─ publish.py       # 병합·업로드 작업(백그라운드), 미리보기
│  ├─ youtube.py       # 구글 OAuth(웹 앱 방식) + YouTube 업로드
│  ├─ templates/       # login / index / legal 화면
│  └─ static/          # app.js, style.css, Sortable.min.js(드래그 정렬)
├─ requirements.txt
├─ .env.example        # 설정 예시 (복사해서 .env 로 사용)
├─ pir.service         # systemd 서비스 예시
├─ apache-ssl-vhost.conf  # Apache 리버스 프록시(HTTPS) 예시
├─ DEPLOY.md           # 서버 배포 상세 가이드
└─ PLAN.md             # 기획서
```

실행 중 자동으로 생기는 파일(저장소에는 올라가지 않음): `.env`, `client_secret.json`, `token.json`, `storage/`

## 3. 준비물

- **Python 3.10 이상**
- **ffmpeg / ffprobe**
  - Windows: `winget install Gyan.FFmpeg` (설치 후 새 터미널에서 `ffmpeg -version` 확인)
  - Ubuntu: `sudo apt install ffmpeg`
  - macOS: `brew install ffmpeg`
- **구글 계정** (업로드할 유튜브 채널이 있는 계정) 과 **Google Cloud 프로젝트** (무료, 결제수단 불필요)
- 서버에 올릴 경우: Ubuntu 서버, 도메인, HTTPS(Let's Encrypt)

## 4. 구글 클라우드 설정 (client_secret.json 받는 법)

유튜브 업로드를 하려면 구글에 "이 앱이 내 채널에 영상을 올려도 된다"고 알려주는 **OAuth 클라이언트**가 필요합니다. 아래를 순서대로 진행하세요.
(구글 콘솔 화면 구성은 가끔 바뀌므로 메뉴 이름이 조금 다를 수 있습니다.)

### 4-1. 프로젝트 만들기
1. <https://console.cloud.google.com> 접속 → 업로드할 **채널이 있는 구글 계정**으로 로그인
2. 상단 프로젝트 선택 → **새 프로젝트** → 이름 입력(예: `pir-uploader`) → 만들기

### 4-2. YouTube Data API v3 사용 설정
1. 왼쪽 메뉴 **API 및 서비스 → 라이브러리**
2. `YouTube Data API v3` 검색 → **사용(Enable)**

### 4-3. OAuth 동의 화면(Google Auth Platform) 설정
1. **API 및 서비스 → OAuth 동의 화면** (또는 *Google Auth Platform*) → 시작하기
2. **앱 정보**: 앱 이름(예: `PIR 업로더`), 사용자 지원 이메일 입력
3. **대상(Audience)**: **외부(External)** 선택
4. **연락처**: 이메일 입력 → 약관 동의 → 만들기
5. **데이터 액세스(범위)**: **범위 추가** → `https://www.googleapis.com/auth/youtube.upload` 추가
6. **대상 → 테스트 사용자**: **업로드할 구글 계정 이메일을 추가** (이걸 안 하면 로그인 시 `access_denied` 오류)
7. **브랜딩**(앱을 "프로덕션"으로 게시하려는 경우): 아래 값 입력
   - 앱 홈페이지: `https://upload.example.com`
   - 개인정보처리방침: `https://upload.example.com/privacy`
   - 서비스 약관: `https://upload.example.com/terms`
   - 승인된 도메인: `example.com`
   (`/privacy`, `/terms`는 이 앱이 로그인 없이 보여주는 페이지입니다. 도메인은 본인 것으로 바꾸세요. 서버 배포 후에 접속 가능합니다.)

### 4-4. OAuth 클라이언트 만들고 JSON 받기 ← 핵심
1. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
2. **애플리케이션 유형: `웹 애플리케이션`** 선택, 이름 입력
3. **승인된 리디렉션 URI**에 아래를 **정확히** 추가 (오타·http/https·끝 슬래시 주의)
   - 서버용: `https://upload.example.com/oauth/callback`
   - 로컬 테스트용: `http://localhost:8000/oauth/callback`
4. **만들기** → 팝업에서 **JSON 다운로드**
   - ⚠️ 클라이언트 보안 비밀번호(`client_secret`)는 **만들 때만 확인/다운로드할 수 있는 경우가 많습니다.** 반드시 이때 받아 두세요. 잃어버리면 새 시크릿을 발급하면 됩니다.
5. 받은 파일 이름을 **`client_secret.json`** 으로 바꿔 프로젝트 폴더(`app/`의 한 단계 위)에 둡니다.

### 4-5. 앱 게시 상태 (토큰 만료 관련)
| 상태 | 설명 |
|---|---|
| **테스트** | 테스트 사용자만 로그인 가능. 토큰이 **7일마다 만료**되어 매주 "유튜브 연결"을 다시 해야 함 |
| **프로덕션(게시)** | 만료되지 않아 한 번 연결로 계속 사용. 로그인 때 "확인되지 않은 앱" 경고가 뜨면 *고급 → 이동*으로 진행 (개인용이면 심사 제출 없이 사용 가능) |

계속 쓸 거면 OAuth 동의 화면에서 **앱 게시(프로덕션으로 이동)** 를 하세요.

### 4-6. ⚠️ 알아둘 점: 심사 전 업로드는 "비공개"로 강제될 수 있음
YouTube API 감사(Audit)를 통과하지 않은 프로젝트로 올린 영상은 **공개로 올려도 비공개로 바뀔 수 있습니다.** (영상에 "확인되지 않은 API 서비스를 통해 업로드되어 비공개 모드로 제한되었습니다" 안내가 표시됨.)
- 코드 문제가 아니라 구글 정책입니다. 공개하려면 [YouTube API 감사 신청](https://support.google.com/youtube/contact/yt_api_form)을 하거나, 올린 뒤 **유튜브 스튜디오에서 직접 공개로 변경**하면 됩니다.
- 15분을 넘는 영상을 올리려면 유튜브 채널의 **전화번호 인증**이 필요합니다.
- API 기본 할당량은 업로드 약 6건/일 수준입니다. (업로드 1건 ≈ 1,600 units / 일 10,000 units)

## 5. 설정 파일 (.env)

`.env.example`을 복사해서 `.env`를 만들고 값을 채웁니다.

```bash
cp .env.example .env          # Windows: copy .env.example .env
```

| 변수 | 설명 | 예시 |
|---|---|---|
| `ADMIN_ID` | 관리자 아이디 | `my-admin` |
| `ADMIN_PASSWORD` | 관리자 비밀번호 (**길고 추측하기 어렵게**) | `긴-비밀번호` |
| `SECRET_KEY` | 세션 쿠키 서명용 랜덤 문자열 | 아래 명령으로 생성 |
| `BASE_URL` | 이 앱에 접속하는 주소. OAuth 리디렉션 주소(`BASE_URL/oauth/callback`)에 쓰임 | 로컬: `http://localhost:8000` / 서버: `https://upload.example.com` |
| `CONTACT_EMAIL` | 개인정보처리방침 페이지에 표시할 문의 이메일 (비워도 됨) | |
| `FFMPEG_PATH` / `FFPROBE_PATH` | ffmpeg 전체 경로. **비우면 PATH에서 찾음** | 서버: 비움 / Windows: `C:\ffmpeg\bin\ffmpeg.exe` |

SECRET_KEY 생성:
```bash
python -c "import secrets;print(secrets.token_urlsafe(48))"
```

> ⚠️ `BASE_URL`은 구글 콘솔에 등록한 리디렉션 URI의 도메인과 **정확히 일치**해야 합니다. 값을 바꾼 뒤에는 앱을 **재시작**해야 반영됩니다.

## 6. 로컬에서 실행하기

```bash
# 1) 가상환경 + 패키지 설치
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux/macOS
# source .venv/bin/activate
pip install -r requirements.txt

# 2) .env 와 client_secret.json 준비 (5번, 4번 참고)
#    BASE_URL=http://localhost:8000

# 3) 실행
uvicorn app.main:app --reload
```

브라우저에서 `http://localhost:8000` 접속 → 로그인 → 맨 위 **"유튜브 연결"** (4-4에서 로컬 리디렉션 URI를 등록했어야 함).

> 접속 주소는 반드시 `http://localhost:8000` 으로 하세요 (`127.0.0.1`로 접속하면 세션/리디렉션이 어긋날 수 있음).

## 7. 서버에 배포하기

Ubuntu + Apache(또는 nginx) 리버스 프록시 + Let's Encrypt HTTPS + systemd 기준 전체 절차는 **[DEPLOY.md](DEPLOY.md)** 에 정리되어 있습니다. 핵심만 요약하면:

1. 서버에 `python3-venv`, `ffmpeg`, `apache2`(+`proxy`,`proxy_http`,`headers` 모듈), `certbot` 설치
2. 코드를 서버(예: `/var/www/html/upload`)에 올리고 가상환경 + `pip install -r requirements.txt`
3. 서버용 `.env`(새 비밀번호·새 `SECRET_KEY`, `BASE_URL=https://내도메인`)와 `client_secret.json` 배치, `chmod 600`
4. `pir.service`를 `/etc/systemd/system/`에 복사해 `systemctl enable --now pir` (uvicorn **워커는 1개**)
5. `apache-ssl-vhost.conf`를 참고해 `ProxyPass / http://127.0.0.1:8000/` 설정, `certbot --apache -d 내도메인`
6. 서버 주소 접속 → 로그인 → **"유튜브 연결" 한 번** (이후 토큰이 `token.json`에 저장되어 자동 갱신)
7. `https://내도메인/.env` 가 **열리지 않는지(403/404)** 반드시 확인

코드를 수정했다면 서버에서 `sudo systemctl restart pir` 로 재시작해야 합니다. (화면 파일만 바뀐 경우에도 재시작하는 것을 권장)

## 8. 사용 방법

1. 로그인 후 맨 위에서 **유튜브 연결** (최초 1회). "✔ 유튜브 연결됨"이 보이면 완료
2. 영상 파일을 **드롭존에 끌어놓거나 눌러서 선택** (여러 개 가능, 촬영 순서와 상관없이 올려도 됨)
3. 각 영상 카드에서 **촬영 시작시간**을 확인 — 기본으로 시간순 정렬됨
   - 순서 변경: 카드를 끌어서 이동 / 왼쪽 번호 입력 / "시작시간순 정렬"
   - 모바일에서는 카드를 **꾹 눌러서** 드래그
   - "추정"은 영상에 촬영시간이 없어 파일 수정시간으로 표시한 것 (메신저로 받은 영상은 메타데이터가 지워지는 경우가 많음)
4. **제목**(기본 `YYYYMMDD PIR풋`)과 **공개 설정**을 확인
5. 둘 중 선택
   - **병합 후 유튜브에 업로드**: 병합이 끝나면 바로 업로드
   - **병합만 하고 미리 보기**: 병합본을 화면에서 재생해 확인 → **"이 영상으로 유튜브에 업로드"** 또는 **"버리기"**
6. 진행률을 확인. 완료되면 **유튜브 링크**가 표시되고 원본·병합본은 서버에서 삭제됨
7. 영상이 이어붙인 곳에서 끊기거나 이상하면 **"안전 모드(재인코딩)"** 를 체크해서 다시 병합 (더 느리지만 가장 안정적)

### 병합 방식
| 방식 | 조건 | 특징 |
|---|---|---|
| 복사(`-c copy`) | 모든 영상의 코덱·해상도·fps·오디오 규격이 같을 때 | 매우 빠름, **화질 손실 없음** |
| 재인코딩(H.264/AAC, CRF 20) | 규격이 다르거나 안전 모드 | 느림(서버 사양 영향), 약간의 화질 손실. 해상도는 첫 영상 기준 |

## 9. 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| `redirect_uri_mismatch` | 앱이 보낸 주소와 콘솔 등록 주소가 다름. `.env`의 `BASE_URL`(끝 슬래시·http/https·서브도메인), 콘솔의 승인된 리디렉션 URI 확인. `.env` 수정 후 앱 재시작. 오류 화면의 "요청 세부정보 `redirect_uri=`" 값이 앱이 실제로 보낸 값 |
| `access_denied` / 앱 확인되지 않음 | OAuth 동의 화면 **테스트 사용자**에 계정 추가, 또는 앱 게시. "확인되지 않은 앱" 경고는 *고급 → 이동* |
| 1주일 뒤 업로드가 안 됨 | 앱이 "테스트" 상태라 토큰 7일 만료 → "유튜브 연결" 다시 하거나 앱을 프로덕션으로 게시 |
| 업로드한 영상이 비공개로 올라감 | 공개 설정을 확인. 공개로 했는데도 그렇다면 API 미심사 프로젝트의 강제 비공개 (4-6 참고) |
| `uploadLimitExceeded` / 할당량 초과 | 하루 업로드 한도 초과. 다음 날 재시도. 15분 초과 영상은 채널 전화번호 인증 필요 |
| 미리 보기를 눌렀는데 업로드됨 | 서버가 **예전 코드로 실행 중**. 코드 교체 후 `sudo systemctl restart pir` |
| 영상이 이어붙인 곳에서 끊김 | **안전 모드(재인코딩)** 체크 후 다시 병합 (휴대폰 가변 프레임레이트 영상에서 흔함) |
| 화질이 떨어짐 | 재인코딩 때문. 같은 규격이면 복사 병합이 되어 화질 손실 없음. 유튜브가 HD 처리를 끝내기 전에는 저화질로 보임 |
| 병합 실패 / ffmpeg 오류 | `FFMPEG_PATH`가 맞는지, 서버는 비워 두고 `ffmpeg -version`이 동작하는지 확인. 로컬 Windows 경로를 서버 `.env`에 넣으면 실패함 |
| 접속 시 502 / 연결 안 됨 | 앱이 안 떠 있음: `systemctl status pir`, `journalctl -u pir -n 100`. 서버 안에서 `curl http://127.0.0.1:8000/login` 확인 |
| `curl -I` 로 확인하면 405 | 정상. `-I`(HEAD 요청)는 지원하지 않음. `curl -s -o /dev/null -w "%{http_code}" URL` 로 확인 |
| 로그인이 계속 풀림 | 접속 주소를 `BASE_URL`과 동일하게 사용 (도메인이 다르면 세션 쿠키가 달라짐) |
| 업로드 중 끊김 | 조각 단위로 자동 재시도·이어받기. 같은 파일을 다시 선택하면 받은 지점부터 이어서 올라감 |

## 10. 보안 · 제한 사항

- **`.env`, `client_secret.json`, `token.json`은 절대 저장소/웹 루트에 공개하지 마세요.** (`.gitignore`로 제외되어 있음.) 서버가 웹 루트(`/var/www/html`) 안에 있다면 웹서버 설정으로 이 파일들을 반드시 차단하세요. 유출됐다면 구글 콘솔에서 시크릿 재발급, 관리자 비밀번호와 `SECRET_KEY` 교체
- 관리자 계정은 1개이며 DB가 없습니다. 비밀번호는 길게 설정하고 **HTTPS**로만 접속하세요
- 작업 진행 상태는 **메모리**에 저장하므로 uvicorn 워커는 **1개**로 실행해야 하고, 서버 재시작 시 진행 중인 작업은 사라집니다
- 한 번에 **하나의 병합/업로드 작업**만 실행됩니다
- 디스크 여유 공간은 업로드할 영상 총 용량의 **2배 이상** 필요 (원본 + 병합본). 업로드 성공 시 자동 삭제
- 규격이 다른 영상의 재인코딩은 CPU/시간을 많이 씁니다 (저사양 서버에서는 오래 걸림)
- 서버 외부로 나가는 트래픽(유튜브 업로드)에 과금되는 호스팅이라면 영상 크기만큼 비용이 발생합니다. 인바운드(서버로 올리는 트래픽)는 보통 무료
- 이 앱은 **개인용**입니다. 다른 사람에게 제공하려면 구글 OAuth 앱 검증과 YouTube API 감사가 필요합니다
